# 安德鲁牙科连锁管理系统

**Andrew's Dental Chain Management System (ADC)**

> 基于系统分析与设计课程的牙科连锁管理系统项目，面向总部、诊所工作人员及患者，提供预约管理、诊疗记录、费用结算、季度绩效核算和运营分析等功能。

## 一、项目简介

安德鲁牙科连锁管理系统（ADC）旨在解决牙科连锁机构在多诊所运营过程中面临的信息分散、预约管理不统一、诊疗与结算数据重复录入以及季度绩效核算困难等问题。

系统以统一业务数据为基础，将患者预约、诊所排班、实际治疗、费用结算和总部绩效管理连接起来，实现诊所业务流程的信息化和规范化，提高运营管理效率，并保证业务数据的准确性与可追溯性。

## 二、项目目标

- **统一患者资料：** 实现患者跨诊所资料复用，统一管理个人信息及过敏记录。
- **优化预约管理：** 根据牙医资质、执业关系及排班情况，提供可预约时隙查询。
- **规范诊疗流程：** 将实际治疗项目、实施牙医、单位数及历史价格统一记录。
- **实现费用结算：** 根据实际治疗记录自动生成费用明细和结算凭据。
- **完善绩效核算：** 按季度核算牙医个人净利润及对应激励。
- **支持运营分析：** 为总部提供跨诊所运营数据及绩效分析。

## 三、系统功能模块

| 编号 | 功能模块 | 主要功能 |
|---|---|---|
| UC01 | 预约就诊 | 创建预约、确认到诊、取消预约、登记爽约、停诊改约 |
| UC02 | 管理出诊排班 | 维护牙医班次、处理停诊及排班冲突 |
| UC03 | 记录治疗 | 记录患者问题、特殊需求及实际治疗项目 |
| UC04 | 结算就诊 | 生成费用明细、计算结算金额、生成结算凭据 |
| UC05 | 维护患者资料 | 管理患者基本信息及过敏记录 |
| UC06 | 维护组织资源 | 管理诊所、牙医、专业资质及治疗目录 |
| UC07 | 核算季度绩效 | 核算个人季度净利润、激励金额及发布绩效结果 |
| UC08 | 运营分析 | 分析诊所运营情况、取消率、治疗结构及绩效 |

## 四、系统用户角色

| 用户角色 | 主要职责 |
|---|---|
| 患者 | 查询可预约时段、提交预约及取消本人预约 |
| 诊所前台 | 办理预约、维护排班、确认到诊及维护患者资料 |
| 牙医 | 记录患者问题、特殊需求和实际治疗 |
| 收费人员 | 核对治疗记录、生成结算单 |
| 总部管理者 | 维护组织资源、管理成本资料、核算绩效及运营分析 |

## 五、系统业务流程

系统围绕一次完整就诊及后续季度管理展开：

```text
患者预约
   ↓
诊所排班与到诊确认
   ↓
牙医记录实际治疗
   ↓
收费人员核对并生成结算单
   ↓
业务数据归集
   ↓
总部季度绩效核算
   ↓
绩效复核与发布
   ↓
运营数据分析
```

## 六、系统架构设计

系统采用前后端分离的设计思路，包含两个主要交互入口：

- **患者微信小程序：** 提供患者身份核验、可约时隙查询、预约及取消等功能。
- **工作人员 Web 管理后台：** 为诊所前台、牙医、收费人员和总部管理者提供相应业务工作区。

两个前端通过统一业务 API 访问服务端，系统按照业务职责划分为以下层次：

```text
患者微信小程序       工作人员 Web 管理后台
       \                  /
        \                /
          统一业务 API
                |
             应用层
                |
             领域层
                |
          基础设施层
                |
        数据映射与事务处理
                |
             业务数据库
```

系统同时设置独立的身份认证与授权组件，实现用户身份、岗位权限及诊所数据范围的统一管理。

## 七、核心业务规则

1. 患者自助取消预约仅允许在预约开始前进行；开始后的取消由前台核实处理。
2. 牙医只能记录本人实际实施且符合资质要求的治疗项目。
3. 治疗单价取自治疗目录，并在实际治疗记录中保存历史价格快照。
4. 一次已完成就诊最多生成一张结算单，重复结算请求返回原结算单。
5. 已结算表示费用凭据已经生成，不代表患者已经付款。
6. 季度绩效根据实际归属收入、医疗用品成本及分摊运营费用计算。

**牙医季度激励计算规则：**

个人季度净利润：

`net_profit = revenue - medical_supply_cost - operating_expense`

个人季度激励：

`incentive_amount = ROUND(MAX(net_profit, 0) × 10%, 2)`

资料不完整时不允许发布正式绩效结果，所有核算结果保留版本及来源依据，确保计算过程可追溯。

## 八、技术架构与设计原则

- 前后端分离，统一业务 API。
- 采用表示层、应用层、领域层、基础设施层的分层设计。
- 通过数据映射器管理跨表业务操作。
- 使用事务保证预约、结算及绩效发布等关键操作的数据一致性。
- 实施基于角色和诊所范围的权限控制。
- 保留关键业务操作的审计记录。

具体开发框架、数据库产品及部署配置以实际项目实现为准。
