## 案例背景

Andrew's Dental Chain（ADC）是 Ivey 商学院案例 *W44694: Data Modeling* 中的连锁牙科集团，由首席执行官兼首席牙医 Andrew Chen 经营。集团计划在数年内把诊所从 15 家扩张到约 30 家。

扩张的瓶颈不在诊疗技术，而在**记录方式**：每家诊所各自维护排班本、纸质治疗单和 Excel 报表，总部只能靠电话和邮件汇总。于是

- 各诊所的「取消率」口径不一，无法横向比较；
- 同一治疗项目在不同诊所写法不同，单价无法追溯；
- 牙医资质与排班脱节，跨诊所调配靠人脑；
- 季度绩效要花掉数个工作日人工核算。

本项目的任务，是把这些「口头约定」变成一套可比较、可追踪的信息系统，并给出可落地的数据结构。

## 建模上的几个取舍

这些是文档里真正花了力气的地方，也是它区别于「把案例抄一遍」的部分。

**1. 业务建模区分「业务工人」和「业务实体」。**
前台、牙医、收费人员是业务工人（人形图标），纸质治疗单、本地记录工具、ADC 信息系统是业务实体（圆圈加斜线）。画法不是装饰——现状图里「人写的纸」和「人」分开，才能说清哪部分工作该由系统接管。

**2. 改进图不把系统画成全自动。**
ADC 信息系统接替了登记、匹配、计价、汇总四类计算性责任，但四个岗位的判断被刻意保留：前台确认资料与预约、牙医确认治疗项目与单位数、收费员决定是否结算、总部管理者决定查询什么。系统的价值是「让判断有依据」，不是「替人判断」。

**3. 用例按执行者目标切分，不按数据实体切分。**
判据是：一个用例结束时，执行者应当能「达到目的后离开系统」。前台排完这次号就走，不该顺带背下「维护全部过敏症」的承诺。因此「保存患者与过敏症」只归 UC05，UC01 的后置收缩为「建立一条绑定患者、诊所、牙医、时间与期望治疗的预约」。

**4. 前置条件只写系统能检测的状态。**
不写「前台已获得患者资料」（系统看不见），改写「ADC 系统中存在拟预约的诊所；拟预约时间晚于当前时间」。这一条改动连带修掉了 UC03 前置与 2a 扩展互相矛盾的问题。

**5. 用例与序列图双向可追溯。**
图 A3 中每条指向「ADC 信息系统」的外部消息都对应一个用例；同一执行者的连续消息可以合并进同一用例（如「提交预约」+「确认预约」→ UC01）。UC05、UC06 在图 A3 中补上了来源消息，否则它们永远是「无源用例」。

**6. 分析阶段把三类关注点拆开。**
实体类图讲领域结构，边界类图对应执行者接口，控制类图一个用例一个控制类。控制类只组织用例流、不自行计算，这条约束让图 C4–C7 的消息箭头真正表示「责任分配」而非数据流动。

**7. 用状态机守住不变式。**
就诊设五个互斥状态，未到诊不得记录治疗，未完成不得生成结算单，已结算不得重复开单。图 C8 的五个状态在第四章落实为 `status` 字段的取值范围与数据层约束——分析与设计之间靠这一条对齐。

**8. 唯一超出分析模型的表，单独交代。**
`CostEntry` 在业务材料和分析模型里都没有对应实体，是为满足 UC07 的「医疗用品成本 + 运营费用」而从交易数据推断出来的。文档没有藏着这一步，而是在表 D1 中注明这是唯一一处扩充及其理由。

## 数据库设计概要

映射遵循标准的结构对应：类→表、属性→列、对象→行；泛化让超类主键充当所有子类主键；一对多把外键放在「多」方；多对多引入关联表。

数据按三层组织，与 ER 图版面顺序一致：

- **主数据**：`Patient`、`Allergy`、`Clinic`、`Dentist`、`Qualification`、`Treatment`
- **交易数据**：`Appointment`（诊疗活动中心）、`AppliedTreatment`（费用与收入的共同来源）、`Invoice` / `InvoiceItem`（结算与审计快照）、`CostEntry`
- **汇总数据**：`QuarterlyPerformance`（只引用牙医，不复制明细）

三个聚合中心串起全库：`Appointment` 向上连患者、诊所、牙医，向下连治疗与结算；`AppliedTreatment` 派生结算明细与成本凭证；`QuarterlyPerformance` 是期末汇总，可重算、结果一致。

## 图表复现

图 A1–A3、B1 不是手工拖控件画的，而是由 Python 生成 SVG、再用无头浏览器截图得到位图，因此可以随文字改动而重排：

```bash
# 生成 SVG 与 .html，输出到 ./output
python tools/figs.py
python tools/usecase.py

# 用 Edge / Chrome 无头模式按 3 倍缩放截图（窗口尺寸需与画布一致）
msedge --headless=new --disable-gpu --hide-scrollbars \
       --window-size=1140,970 --force-device-scale-factor=3 \
       --screenshot=output/figA2.png output/figA2.html
```

脚本中的 `OUT` 取脚本自身所在目录下的 `output/`，换机器时无需改路径；`figs.py` 会自动生成 `output/_render.sh`，其中的截图命令含绝对路径，换机器后按上面这条命令的格式替换路径即可。字体使用宋体，非 Windows 环境需替换 `FONT` 变量。
