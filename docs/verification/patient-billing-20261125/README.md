2026-11-25，范围为负责人批准的最小数据调整和演示支付闭环。所有门店、医生和患者为明确标记的虚构测试资料。演示不扣真实款，不调用微信支付。

## 现在的操作方法

管理端访问 https://andrewdental.cn ，完整演示使用已有的 `cloud-demo` 账号；口令沿用受控的云端联调登录资料，不写入项目文档。日常导航“费用与缴费”查看挂号账单、诊疗账单及退款；齿轮菜单的医生管理可编辑职称、擅长和简介，医生详情中可设置各门店挂号费。`cloud-admin` 为总部配置角色，其他岗位继续按实际授权访问。

微信开发者工具导入 `apps/patient-miniprogram`，使用已配置的正式 AppID；构建目录为 `dist/miniprogram`，请求域名为正式 HTTPS。首次只填写姓名、生日、联系电话及过敏声明，地址、紧急联系人和邮箱可后补；已有档案账号继续使用当前本人关联，不重新登记。

预约依次选择门店、看牙检查或洗牙洁牙、日期、医生及真实时段，查看医生职称、方向、简介和挂号费。零挂号费直接预约；收费预约保留号源五分钟，进入“我的费用”后点击演示缴费，成功才生成预约。退出待缴或超时会释放保留；已预约后合法取消，同事务全额演示退款。诊疗实际发生并开具唯一费用凭据后形成诊疗待缴账单；有权限的收费人员可演示收款、填写退款原因并全额退款。原Invoice和R1保留原口径。

小程序重新编译命令：在 `apps/patient-miniprogram` 执行 `npm run verify`，再点击微信工具“编译”。管理端修改后在 `apps/admin` 执行 `npm run verify`；云端当前已运行构建版本，本地编译不会自动发布。云端运行方式、摘要及备份记录见 application-update.json。

## 验证边界与未完成项

微信模拟器原生确认框已经显示并截图，但其 `Tool.native` 自动点击未响应。联调只对 `showModal` 的确认返回值作自动处理并在结束后还原；微信登录、业务方法、HTTP、金额及数据库没有mock。手机手动完成这次演示支付仍待确认，不能将模拟器通过写为真机全流程通过。部分截图调用超时如实记录于 device-integration.json。

真实微信支付未接商户号、商户权限和渠道适配，本轮始终显示“演示支付，不扣真实款”。小程序ICP备案由负责人自行办理，正式发布未执行。

Spec Kit当前状态见specs/001-system-specification/tasks.md。Q01按自动化检查和日常使用确认，不要求招募、培训或人工记录；Q03/Q05的实际结果分别见性能和恢复专题。正式发布与真实完整季度事实单独记录。
