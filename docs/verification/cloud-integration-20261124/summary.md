绑定页提交成功后仍可连续提交，申请、读取状态与实际绑定的提示容易混淆。已增加当前身份的“申请已提交、待前台核验”状态和重复提交保护；成功回执不冒充绑定已完成，人工批准后才显示有效绑定。新增3项测试，患者端合计30项通过。跨身份切换清除提示，未知结果仍保留原幂等请求。旧历史申请保留，未清理记录或改变绑定规则。微信工具清理本项目编译缓存后，真实运行状态与截图通过；第二个微信的当前有效绑定保持不变，见 `binding-ui.json`、`binding-pending.png`。

## 使用方式

管理端使用 `cloud-demo` 体验全部已授权模块；`cloud-admin` 用于总部配置，其他独立岗位为 `cloud-frontdesk`、`cloud-dentist`、`cloud-cashier`。密码独立生成，见本机 `D:\secrets\AndrewDental\CloudIntegration\云端联调登录资料.txt`，不写入仓库或聊天。

患者端当前普通构建指向正式域名，公共/私有配置均开启域名校验。当前虚构患者档案已按验收流程绑定第二个微信；原微信不能直接查看该档案属于正确结果。管理员看到的是同一云库中的原预约记录。

本机 `Start-LocalIntegration.ps1` / `build --local-preview` 仍是旧localhost环境入口，不要用它启动云端演示。正式域名构建只运行 `apps/patient-miniprogram/scripts/build.mjs`，在原项目微信工具中编译/预览即可。

运维、证书及回滚见 [部署手册](../../../ops/runbooks/deployment.md)，微信操作见 [联调手册](../../../ops/runbooks/wechat-integration.md)。候选摘要/预检/备份/证书/数据库/浏览器/身份结果均在本目录JSON；私钥、密码、原始令牌与备份内容只在受控私密目录。
