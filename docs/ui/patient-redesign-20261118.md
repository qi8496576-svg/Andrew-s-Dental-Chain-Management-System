# 患者端 UI/UX 改版实施记录

日期：2026-11-18。范围为原生微信患者端；沿用 SF01 微信登录、SF02 本人档案核验绑定、UC01-S1 预约、UC01-S3 自助取消、UC05 本人资料只读及 UC06 已授权目录投影。Constitution、Spec、Plan、既有契约与 ERD 保持原样。

## 问题与方案

原首页实际为占位入口，启动后首先进入登录页；六个页面缺少稳定导航；预约把资料、项目、时间与确认平铺在长表单中；记录缺少状态分组；绑定说明难以区分登录、申请与批准；各页字号、按钮、间距和空状态没有统一标准。

本次采用安德鲁自己的深青绿 #176959、暖白卡片、浅绿背景和少量暖金装饰。以原生四项底部导航固定“首页／预约／记录／我的”，首页突出预约和四个服务卡片。图标由项目脚本绘制，不使用医院 Logo、照片或专属内容。品牌图形为 A 字标与几何装饰。

参考[湘雅二医院公开预约流程说明](https://www.haodf.com/neirong/wenzhang/7926627250.html)中按医生、日期、时段逐步选择、核对就诊人的组织方式。该资料为历史公开说明，未取得该院当前小程序完整界面，不据此宣称逐屏比对。仅借鉴服务入口、就诊人状态和分步确认的交互原则；安德鲁的取消、身份、诊疗状态等规则全部以本项目规约为准。

| pages/patient-bindings/index | 保留人工核验链，重做 | 申请线索 → 前台核验 → 刷新生效；已绑定状态与换号办理说明 |

新增共享 presentation.ts 只负责导航与一次性的门店/记录筛选选择；不存患者身份、不持久化会话、不判业务成功。共用 app.wxss 样式及同一套线性图标。原有 session、http、authentication 服务、bookingPayload、幂等键及服务器授权校验继续复用。

预约的医生列表由实际 Candidate 返回的 dentist_id/name 去重得出，只筛选已加载候选；“加载更多”继续请求服务端游标。更换门店、项目、日期或医生会清除原时隙和确认状态。提交仍以原始 schedule_id/starts_at 和后端最终资格、执业、班次及占位校验为准。

预约记录将 COMPLETED 与 INVOICED 归入“已完成”筛选，但卡片保留其实际状态。INVOICED 明确不等于已付款。患者取消仅在 SCHEDULED 且开始前显示为可用，服务端继续复核正常班次等条件；到诊、完成、结算或取消后的状态不可通过界面绕过。

## 接口限制与保留边界

患者端可读门店/项目基础目录，已绑定后可查询候选时段及本人资料和预约。现有目录只提供 id/label/code/active；患者不能调用员工医生详情，接口也未提供患者可读的医生照片、职称、擅长、门店地址、服务说明及价格。因此本版展示真实目录和候选医生姓名/时间，不加入虚构照片、履历、地址、营业时间或价格。完整诊疗病历同样不在现有患者接口范围内；“就诊档案”如实展示本人资料、过敏及可跳转的预约/就诊状态。

未登录时首页不伪造门店，展示明确登录入口；登录但未绑定时不会拉取或显示患者资料。已有绑定在验收中保留，未为展示未绑定状态而撤销用户绑定。未绑定场景通过隔离单元测试验证。

## 验证与使用

启动仍使用项目根目录 `tools/preview/Start-LocalIntegration.ps1 -OpenWeChat`。普通 build 连接正式域名，本机使用 build:local。打开项目后从首页进入四个底部模块；登录、资料和绑定为详情页。后端和真实 MySQL 继续使用同一 localhost:19443 入口。

验证入口：`tools/preview/check-patient-ui.mjs`（真实工具七页截图、登录状态、导航与选择），`tools/preview/check-patient-admin.mjs`（真实预约/取消及管理端到诊联动），`tests/unit/mini-ui.test.mjs`（未绑定隔离、迟到响应、路由和时隙失效）。构建脚本在本机原生编译器可用时同时验证源及产物的全部 WXML/WXSS、原生 tab 图标和路由；不具备编译器时明确报告 native_wxml_wxss_compiled=false。

最终截图和运行报告位于 `docs/verification/patient-ui/`；双端业务证据见 `docs/verification/local-patient-admin.json`。微信工具本机条件沿用已有私有 urlCheck=false 与自签名 HTTPS，正式合法域名/备案、真机及九人 Q01 易用性验收仍未完成；本次开发者操作不替代这些验收。
最终核验：最终构建的 TypeScript、源及 dist 的七页 WXML/八份 WXSS、四项 tab 路由与图标检查通过；22 项单元回归通过。负责人已反馈“新版首页及其他页都可以看到，登陆成功”。此前八项真实运行交互检查通过，但其截图早于最终共享样式修复，仅保留为中间记录。最终自动截图与改版后完整创建/取消/管理端到诊重跑受微信官方 auto 命令停在获取 AppID 权限及截图超时阻塞，未宣称通过；汇总见 docs/verification/patient-ui/final-result.json。
