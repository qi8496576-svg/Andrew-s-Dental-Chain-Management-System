## Dentalpin 实际研究

使用提供的公开 Demo 账号实际登录 [Dentalpin](https://demo.dentalpin.com/)，检查业务页、齿轮设置、列表筛选及代表性新增面板。浏览器拦截除认证外的写请求，只打开和取消表单，不向参考系统保存、删除或启停任何业务数据。以下是参考产品的观察，不是安德鲁牙科新增需求。

### 左下角齿轮与基础配置

实际齿轮链接到 `/settings`，进入有独立分类与返回位置的配置体系；它与 Home/Schedule/Patients 等日常主导航分工不同。没有观察到齿轮复制整份业务导航。安德鲁牙科采用底部独立展开层、配置总览和独立配置路由，保留这一业务分工。

| 配置分类 | 实际包含的入口 | 页面与字段观察 |
| --- | --- | --- |
| General | Clinic Information | 诊所名称、税务/法律名称、地址、电话、邮箱、时区、货币及 Edit information |
| Workspace | Cabinets、Clinic hours、Professional schedules | Cabinets 为诊室资源，列表含名称/颜色；新增含 Name、Color、Cancel/Create。Clinic hours 为一周模板、特殊日期、时间输入、Add shift/Save。Professional schedules 有选择专业人员的提示与人员读取；本次未取得单个医生的可编辑表单 |
| People | Clinic Users | 说明用于诊所用户及角色，实际请求了用户目录；Demo 本轮没有呈现可操作用户行或独立角色 CRUD 表单，不能声称核实其角色编辑字段 |

| Account | Profile、Language | 深层页显示相应标题和说明，本轮没有呈现可编辑字段；仅核实入口，不声称已测试个人资料/语言保存 |

不存在足够证据将 Cabinets 称为“床位”，也没有核实一个独立的“角色管理”菜单。对 Demo 未呈现的医生/角色编辑细节不作推断。Billing preferences、报价有效期/提醒/公开链接、文档抬头等深层页实际显示 “You don't have access to this section”；只能记录已观察到的入口及说明，不能记录为内部表单已经核实。完整截图、可见文字、字段、链接及网络状态保存在：

- `docs/verification/dentalpin-settings/observations.json`：九类配置及诊所、诊室、营业时间、治疗目录等。
- `docs/verification/dentalpin-focus/observations.json`：用户、医生排班、治疗目录复核。
- `docs/verification/dentalpin-remaining/prior.json`：发票序列/税率的列表与新增表单；第一轮后续页面网络等待超时，已保留此前观察。
- `docs/verification/dentalpin-remaining/observations.json`：其余通知、个人等配置细项及权限受限结果。

## 当前问题与实施结果

原页面把组织资源、员工账号、岗位授权同时放入左侧导航和管理中心；齿轮打开居中对话框，其入口层次与业务区重复。资源入口仍进入同一个带分类标签的总页面；首页缺少可办理的当日工作信息，各页表格、按钮、标题缺少统一视觉。

现已调整为：

| 区域 | 入口 |
| --- | --- |
| 日常主导航：诊所业务 | 预约管理、出诊排班、患者资料、患者身份绑定 |
| 日常主导航：诊疗与费用 | 医生工作台、结算就诊、费用凭据查阅、治疗价格纠错 |
| 日常主导航：经营管理 | 运营分析、季度成本核验、季度个人绩效 |
| 左下角齿轮：基础配置 | 诊所管理、医生与执业资质、治疗项目与价格目录、专业资质目录、过敏与服务基础资料 |
| 左下角齿轮：人员与权限 | 员工账号与密码、角色/岗位/诊所授权 |

首页另保留工作区入口，显示所选门店当日真实预约统计、最多六条待办安排和已授权业务快捷入口。没有权限的统计不请求；超过 100 条时明确说明仅统计已加载记录。

齿轮支持再次点击收起、Escape、外部点击关闭和跳转后关闭；Escape 后焦点返回按钮。配置分组只含当前已授权条目，入口与主导航没有重复目的页。五种基础资源分别使用 `/settings/clinics`、`dentists`、`treatments`、`qualifications`、`allergies` 的独立页面；账号及授权保留 `/staff-accounts`、`/clinic-grants`。配置页面有独立标题、说明、当前位置、返回系统管理入口和新增操作；支持地址直达、刷新。原 `/organization-resources` 旧链接仍可访问。

统一浅色侧栏、青蓝品牌色、线性图标、标题层级、表格、筛选、输入框、弹窗和状态标签，不使用 Dentalpin 品牌素材。资源维护从列表进入详情，返回后保留筛选和已加载页，避免长列表把详情推到页面底部。资源目录新增名称/代码与启停筛选；员工账号新增搜索/状态筛选；授权记录区分有效、未生效、已结束、已撤销并显示可取得的账号名称。目录和账号筛选针对已加载数据，界面明确显示数量，并保留真实游标“加载更多”。

继续复用原资源表单、API、ETag、幂等命令、未知结果查询、资质核验、执业关系、停用后的未来影响提示。未增加无后端支持的删除操作。授权管理从有效总部授权推导可管理诊所，不把已撤销/过期记录混入；保留四种已批准岗位，不创建虚拟管理员角色。

另修复预约页的实际权限兼容问题：原先查看列表依赖治疗目录/候选时段加载，只有列表权限时会被无关请求阻塞。现在列表独立读取，仅在具备相应能力时显示候选查询和创建表单；门店名称不可读时仅使用当前身份已返回的真实诊所 ID 作选择，未伪造门店详情。后端访问控制保持原样。

## 实际验证与边界

本轮完整类型检查、22 个测试文件的 45 项 Vitest 全通过；最后资源详情视图调整另做类型检查及资源模块测试。生产构建通过，并更新本机管理端容器。修复部署工具只打包旧 dist 的问题：刷新脚本现在先构建当前源码，启动脚本保留最新本机前端镜像。后端和 MySQL 容器 ID 在更新前后相同。

真实 Edge + 同一个持久化 MySQL、无 API Mock 的 11 组验收通过：

1. 日常导航与配置目的页不重复，齿轮展开/收起/Escape/外部点击。
2. 五种独立资源页面直达、跳转、刷新、面包屑。
3. 新建专业资质，刷新后仍存在。
4. 新建治疗、168.00 精确价格及必需资质关联。
5. 新建医生、核实证书及诊所执业关系，刷新后仍存在。
6. 新建未被引用目录项、停用和状态筛选。
7. 新建虚构员工及核实后密码管理。
8. 真实授予仅查看预约的权限，列表正常；隐藏无权创建入口；配置路由拒绝，账号管理 API 403。
9. 撤销该授权，原员工会话下一次预约请求即返回 403。
10. 全模块演示管理员的 16 条既有日常业务/办理路径均可访问，无页面脚本错误。
11. 原普通前台依旧不能访问系统配置及账号 API。

结果与截图：`docs/verification/admin-workspace/results.json`、`home.png`、`gear-menu.png`、`treatments.png`、`doctor.png`。新增数据均显式命名“本机验收/虚构”，没有真实患者资料；临时员工权限已撤销，审计历史保留。全部路径可达不等于本轮重新执行所有诊疗、结算和季度边界场景，后者沿用原模块验收。

资源详情视图最终调整后，`docs/verification/admin-demo-browser.json` 另记录一次管理员登录访问 20 条既有路径、8 个配置目的页、五类资源的列表/详情/返回操作、已有诊疗上下文与真实费用凭据读取，以及普通前台拒绝访问。该轮通过、无 API Mock，也未新增业务记录。汇总见 `docs/verification/admin-workspace/verification.json`。

直接读取本机数据库再次核实业务结构仍为 **19 表 / 163 字段 / 30 外键**。此前患者取消预约仍为 CANCELLED，管理端确认到诊仍为 IN_PROGRESS；证据在 `docs/verification/local-patient-admin.json` 的 `database_verification`。本轮未改患者端、后端或共享业务结构；微信页面到管理端的全新预约闭环未在本轮重新执行，不以数据库读取替代新的微信实测。

ERD 没有床位/诊室实体，本轮不添加床位页面、占用关系或虚假数据。真实收款、报价、自动回访、税率、模块安装等不属于本项目已批准业务，不因参考系统存在就追加。正式域名/备案与真机微信条件、规定九人易用性、完整性能/恢复和真实季度验收继续按现有 Spec Kit 清单推进，本轮不据此勾选 T050—T056。

## 启动与演示

从项目根目录 PowerShell 执行：

```powershell
.\tools\preview\Start-LocalIntegration.ps1
```

访问 https://localhost:19443 。全模块管理员演示账号为 `admin-demo`，密码见本机 `D:\secrets\AndrewDental\LocalPreview\教师演示登录.txt`；其他岗位见同目录 `预览登录资料.txt`。该管理员通过正常接口配置四种岗位与具体能力，没有服务端超级用户绕过；保留既有授权有效期。不要把账号密码写入源码或研究截图。

建议演示顺序：

1. 打开首页，查看真实门店/今日安排；打开齿轮，确认业务主导航没有同名配置项。
2. “专业资质目录”→“医生与执业资质”核实证书与执业关系→“治疗项目与价格目录”维护必需资质。列表进入详情并返回。
3. 返回主导航“出诊排班”创建未来有效班次，“预约管理”查询对应时段并办理。确认/取消/爽约/停诊改约继续使用原独立操作页。
4. “员工账号与密码”及“角色、岗位与诊所授权”配置实际员工；用受限账号验证可操作范围，撤权后下一请求生效。
5. 患者端仍按[本机双端联调手册](../../ops/runbooks/local-integration.md)运行，与此管理端使用同一后端/数据库；新增资源不会凭空生成排班或自动扩大权限。

修改前端后，从根目录执行：

```powershell
& .\tmp\toolchains\node-v24.22.1-win-x64\node.exe tools/preview/refresh-admin-preview.mjs
```

该命令只构建并替换本机管理端，保留已有后端/数据库。`check-admin-workspace.mjs` 会创建明确标识的虚构验收资料，只用于当前本机专用测试库；`check-admin-demo.mjs` 用于既有管理员页面/配置详情往返和既有诊疗、费用凭据的只读回归。
