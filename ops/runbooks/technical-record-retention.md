# TD-01 技术资料保留方案（负责人已确认）

2026-11-25，负责人明确同意“一期不启用自动删除”。一期课程及虚构业务验收采用“失效控制、保留证据、不启用自动删除”。这份方案不执行清理，也不改变业务历史、审计至少一年和备份可恢复30天的既定要求。

| 资料 | 一期处理 | 原因及访问 |
| --- | --- | --- |
| Subject、ExternalIdentity、StaffAccount | 保留；按停用、撤权或解除关联控制访问 | 避免历史主体、业务操作者及审计引用断开 |
| Session | 退出、过期、停用及恢复后失效；不自动删除行 | 失效会话不能访问；保留安全定位证据 |
| LoginThrottle | 按既有时间窗口计算限制；不安排物理清理 | 不通过删除绕过限流，不添加新的业务保留时限 |
| BindingRequest、BindingEvent、CurrentPatientBinding | 当前关联按业务替换；申请及事件历史保留 | 换号后旧账号失权，原核验和办理主体可追溯 |
| AccessGrant、GrantClinicScope、GrantCapability | 撤权立即生效，保留授权历史 | 不把隐藏菜单当访问控制，不删除引用来抹去授权过程 |
| RequestReceipt | 保留成功回执及其对象引用，不设擅自推断的短期重放截止 | 恢复后原请求键可核实和幂等重试 |
| AuditEvent | 继续至少一年、只追加、授权读取 | 运行账号没有UPDATE/DELETE，不由备份30天策略删除在线审计 |
| 业务表 | 保留现有历史，不在技术清理中物理删除 | 开票、退款、成本及季度结果继续可追溯 |

磁盘容量及备份链滞后应监测告警；不能自动删历史来解容量问题。未来如果需要清理，应另行提出逐表时限、法定/业务依据、引用及幂等影响、归档和恢复办法，由负责人确认后实施。

批准该方案仅关闭“一期是否启用自动删除”的决策，不等于正式生产发布许可。T055还依赖实际患者/管理者验收、完整Q03和恢复验收。
