# 运营分析的营业名单与工作日历来源

分析本身不修改来源业务。取消、治疗、技能及当前发布结果直接从授权业务库的一致只读快照取数；无法重建的历史状态返回不可计算，不以当前状态替代。

原A1a需要有来源的期间营业名单、接入/使用证据和工作日历。配置项 `adc.analytics.evidence-file` 指向部署人员受控提供的绝对JSON文件路径，例如通过启动参数 `--adc.analytics.evidence-file=/run/adc/analytics-evidence.json` 读取；本地文件放D盘。文件随版本部署并留来源与摘要，不由网页上传、编辑，也不新增业务表或接口。未配置时，相关指标明确返回来源不足，其余分析仍可使用。

文件结构为 `version`、`reference`、`rosters`、`calendars`。前两项为经核实的资料版本和来源引用；两个列表可以为空，不代表业务值为零。

每项rosters包含：`start`、`end`（完整覆盖评价期间、起点含终点不含的带时区时间），`reference`（正式营业名单依据），`verified_at`（有证据的核实时点），`clinic_ids`（该期间完整营业名单中的原Clinic ID字符串）。无范围核实依据不能把当前is_active当作整个历史季度营业名单。只有营业名单、患者服务审计、期间预约及实际治疗使用证据齐备，才返回可核验覆盖率；缺项列出，不补成零或假定已接入。

每项calendars包含：`start`、`end`（覆盖实际资料齐备至全部发布期间），`reference`、`verified_at`，以及`day_start`、`day_end`（来源明确的单个工作日工作时间）和`holidays`（来源确认的法定节假日日期列表）。按原周一至周五且节假日除外计算，资料等待单列。不能自行填入8小时、任意节假日或额外调休政策作为已批准规则；缺少经确认的工作时间或完整日历时保持不可计算，正式评价前核实来源。测试中的09:00—17:00及虚构假日仅用于算法验证。

资料核验时间晚于查询cutoff、范围不覆盖、批次人员未全部同口径发布或缺失来源时，不宣称达到SC-001/SC-002。T056仍需真实上线首完整季度、正式名单/接入证据、工作日历及人员复核；开发测试不代替该验收。
